# 风格配方：怎么描述一种视觉语言

> 目标读者：要给 `assets/lib/styles.js` 加第 13 种风格的人（或者 AI）。
> 这份文件不定风格，只定**写风格的方法**。照它写，风格能落地；不照它写，
> 写出来的是形容词大礼包 —— 读着都对，落到 canvas 上一行代码也写不出来。

---

## 0. 先分清两件事

风格描述有两种，用途完全不同，别混：

| 形态 | 例子 | 谁在用 | 优点 | 缺点 |
|---|---|---|---|---|
| **文本配方** | `styles/watercolor.md`（11 章） | lemo-opuscar / cinecode（58 份） | 覆盖广、能读能改、无限变体 | 每次都要 LLM 现场写代码；不确定；费 token |
| **代码实现** | `STYLES.watercolor`（218 行） | 本项目（14 种） | 一条命令出片、零 token、确定性、可回归 | 加一种要写代码；上限就是写过的那些 |

**本项目走代码路线，不动摇。** 所以配方的正确用法不是「抄进来当 prompt」，
而是当两样东西：

1. **上游设计文档** —— 写新风格前先写一份自己的配方，再照着它写代码。
2. **下游审查清单** —— 拿它查已有风格，看哪些特征被漏了。

> 直接搬 58 份 md 进仓库，等于把「`--theme=glass` 一条命令出片」降级成
> 「每次让模型读 4000 字再现场画」，是退步，不是进步。

## 1. 十一章骨架（以及它对应到哪段代码）

每章不是凑数，缺一章就会出现一类固定毛病。括号里是本项目的落点。

| # | 章节 | 回答什么问题 | 缺了会怎样 | 落在哪个钩子 |
|---|---|---|---|---|
| 1 | **本质 & 它不是什么** | 一句话说清它靠什么成立；明确排除 3–4 个近亲 | 风格漂移，做出来像"四不像" | 文件头注释 |
| 2 | **材料与渲染** | 纸/墨/光/几何的最小构成，**带数字** | 只有形容词，代码无从下手 | `bg()` / `card()` / `bar()` |
| 3 | **色彩逻辑** | 谁是白、谁是黑、几个色相、强调色怎么复用 | 用满调色板，画面变脏 | `theme` 对象 |
| 4 | **字体与字幕** | 字族、字重、字距、行高、字幕规格 | 中文挤成一团或字重错位 | `type` / `text()` |
| 5 | **运动质感** | 主动作是什么、次要动作是什么、缓动曲线 | 全片匀速平移，像 PPT | `motion` / `enter()` / `boil()` |
| 6 | **运镜语法** | 这种风格允许哪几种运动，各自表达什么 | 什么镜头都上，风格被运镜带跑 | `CAM.move()` 的 line |
| 7 | **声音** | 配器、音效来源、混音特征、响度 | 视觉是水彩，声音是电子鼓 | `--audio` / `audio-master.js` |
| 8 | **招牌动作** | 3–7 个「只有这个风格做才成立」的动作 | 换了风格没人看得出区别 | 各钩子里的特殊分支 |
| 9 | **介质陷阱** | 这种材质天然会踩的坑 | 每加一个新风格重踩一遍旧坑 | 代码注释 |
| 10 | **实现映射** | 每个特征对应哪个函数、哪几个参数 | 配方写完发现落不了地 | 全部 |
| 11 | **可变空间** | 哪些必须固定，哪些留给内容决定 | 模板化，十条片子一个样 | 模板参数 |

第 1、9 章是这套方法里最值钱的两章，中文互联网上的「风格 prompt」几乎都没有。

## 2. 每章写到什么颗粒度

### 第 1 章：本质 & 它不是什么

一句「本质」+ 三到四条「不是」。本质要能被证伪：

```
✗ 水彩：柔和、通透、有艺术感        ← 三个词，一条代码也写不出来
✓ 水彩：一张暖白棉纸，所有形体都由半透明笔触叠出来，纸本身就是白
      不是水墨（有颜色，不是墨阶）
      不是厚涂（没有刀痕、没有堆料）
      不是儿童绘本（没有蜡笔、没有描边）
      不是矢量图加个水彩纹理（纹理不是画出来的，是纸）
```

「不是」要挑**近亲**，不是挑远房。挑了远房等于没排除。

### 第 2 章：材料与渲染

每个名词后面必须有数。没有数的描述等于没写：

```
✗ 笔触有粗细变化
✓ 笔触宽度按 brush/leaf/trunk 四种剖面变化，附加 ±22% 值噪声；
  3–9 条刷毛轨迹，不透明度 30–85%，每条有随机断点和提前收笔 → 这就是飞白
```

判定标准：**读完这一章，另一个人能写出 60% 的代码。**

### 第 3 章：色彩逻辑

必须先答「纸是什么颜色」，因为它就是这套风格的白。然后：

- 色相数量上限（水彩 3–5 个 + 墨色）
- 深浅靠什么（更多遍数？更深的颜料？网点密度？）
- 强调色几条、复用在哪
- 给 2–3 组现成配色，带 hex

### 第 4 章：字体与字幕

中文项目必须单独一节，因为西文字体选型规则在中文上全不成立：

- 等宽族必须挂中文字体，否则中文 fallback 到衬线，和英文对不上
- 中文负字距会把字挤到一起 —— 中文的 tracking 只能是 0 或正值
- 字幕最长几行、多大、停留在什么背景上（水彩：**在纸上，不在框里**）

### 第 5 章：运动质感

一个风格的「主动作」只有一个。写清主次：

```
水彩：主动作 = 画上去（painting-in），次要动作 = 画完后轻微摇摆
      摇摆幅度 0.006（树）~ 0.03（草），公式 sin(1.15t+φ) + 0.4sin(2.7t+2φ)
```

摇摆用**两个不同频率的正弦叠加**，单个正弦是机械摆动，一眼假。

### 第 6 章：运镜语法

写成表：**运动 / 表达什么 / 能服务什么内容**。这是菜单不是路线，
模板只从中挑 1–2 个，不排满。

### 第 7 章：声音

- 配器（具体乐器，不是"舒缓的音乐"）
- 音效从**画面材质本身**来（水彩：画笔擦纸声，不是 whoosh）
- 混音特征：人声比音乐高几 dB、音乐让人声多少、最终多少 LUFS

### 第 8 章：招牌动作

判定标准：**这个动作换到别的风格里就不成立**。

```
水彩的「雾擦」：纸色雾气把画面洗回白纸 → 换到蓝图风里毫无意义
半调的「印版迟到」：某块颜色晚半秒才印上 → 换到水彩里是 bug
```

每条后面跟一句「适合什么内容」，否则用不上。

### 第 9 章：介质陷阱（**这一章最重要**）

记的是**真踩过的坑**，不是想象的坑。写清现象 + 原因 + 修法：

```
离屏洗色条画短了 → 高形状顶部被削平 → 条要画到画框外
半透明在画布边缘结束 → 叠到别的层上有硬缝 → 往下延伸 + 渐变淡出
在 render(t) 里建笔触用了全局 RNG → 多 worker 各渲各的 → 必须包 seed
```

本项目的固定陷阱清单（所有新风格都要自查）见第 4 节。

### 第 10 章：实现映射

一张表：特征 → 函数 → 参数。写完这章如果发现某条特征没有落点，
要么加钩子，要么砍掉这条特征 —— 不要留着当摆设。

### 第 11 章：可变空间

明确「哪些由内容决定」：结构、开场、结尾、构图比例、要不要测量数值。
给 3 个结构变体 + 3 个开场 + 3 个结尾，证明这套风格不止一种用法。

## 3. 审查已有风格：五问

拿任何一份配方去查我们已有的 14 种，只问五句：

1. **纸/底是什么？** 有没有真的画出来，还是一句 `fillRect` 纯色？
2. **它的白在哪？** 如果纯白 `#FFFFFF` 出现在非高光位置，风格就已经假了。
3. **签名特征有没有？** 水彩的积色边 + 飞白、半调的网点角度、剪纸的投影层数。
4. **主动作是一个还是零个？** 零个 = 画面死；多个 = 互相打架。
5. **有没有留下介质陷阱的注释？** 没有注释说明没踩过，那大概率还会踩。

> 实测记录：2026-11-17 用这套问法查 `STYLES.watercolor`，查出两处真缺陷 ——
> 缺飞白（第 3 问）、`bar()` 建好收笔渐变后被 `void tg` 丢弃（第 5 问）。
> 两份都是配方直接指出来的，不是猜的。

## 4. 本项目固定陷阱清单

每加一个风格，逐条过：

| 陷阱 | 现象 | 修法 |
|---|---|---|
| **确定性** | `qa.js` 报「结果不可复现」，多 worker 渲染不一致 | 纹理走 `rng(seed)` / `hash(i,t)`，绝不 `Math.random()` |
| **画布尺寸** | 换个 9:16 就全部错位 | 一切尺寸从 `W/H` 与 `SF=√(SX·SY)` 推，不写死 1920 |
| **背景透明** | 转场时闪底色 | `bg()` 必须铺满整块画布 |
| **留边** | 运镜后四边露出画布底 | 背景要有 1.2 倍冗余，或运镜前先 `scale` 放大 |
| **中文断行** | 长中文标题溢出卡片 | 用 `text()` 的换行逻辑，不要自己 `split('')` |
| **字体回退** | 换台机器字重全变 | 走 `F`（已探测本机可用字体） |
| **缓存串味** | 改了参数但画面不变 | `noiseTile` / `bgCached` 的 key 必须包含全部参数 |
| **渐变进 rgba** | 传 CanvasGradient 给 `rgba()` 直接崩 | 先判 `typeof color === 'string'`，退化处理 |

## 5. 我们做不了的（别硬抄）

58 份配方里有相当一部分依赖我们技术栈之外的东西。**硬抄只会做出赝品**：

| 类型 | 代表配方 | 为什么不行 |
|---|---|---|
| **WebGL / shader** | risograph（三通道当三块印版）、tilt-shift、glass-product 的折射 | 我们是 Canvas 2D。riso 我们的做法是「真网点 + 错版」，观感到位但物理不同 —— 能接受，要说清 |
| **实拍 / 胶片质感** | backrooms、archive-lighttable、cinematic-realistic | 要真实素材与噪点模型，属 VideoGen 领域 |
| **复古像素** | pixel-rpg、ascii-crt | 与本项目「现代 2D」定位冲突，明确不做 |
| **原生 3D** | claymation、brick-toy、lowpoly-island | 我们的 `clay` 是 2D 拟软塑，不是真 3D。再加同类会重复 |
| **依赖外部素材** | living-screencast、visual-proof | 要真实录屏/截图 |

能给我们的，是这些配方里的**语法**（构图规则、色彩逻辑、运动质感、陷阱），
不是它们的**实现**。

## 7. 写一份新配方的流程

```
1. 写配方（本文件第 1 节的 11 章），控制在 150–250 行
2. 第 10 章填「实现映射」时，逐条确认有钩子接得住
3. 拿第 3 节的五问自查一遍
4. 写代码，只动 bg / overlay / text / card / bar / boil / enter 七个钩子
5. 出 12 宫格静帧（style-gallery.html）→ 肉眼看
6. 出一支 13 秒片 → 跑 qa.sh + h2v qc
7. 把第 9 章里新踩的坑补回本文件第 4 节
```
