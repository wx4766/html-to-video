# 文案：聪明、够短、句句有着落

一支短片只装得下一个念头，也只留得下很少的字。

这一份是**写文案时的方法**，不是审美偏好。写 story JSON、写旁白、写屏幕文字、改稿，都按这个走。
判据来自 cinecode 的 `references/writing.md`（MIT © 2026 Sarp Yıldız），按中文与我们的模板结构做了改写。

目标：**聪明、少解释、点得准**。

---

## 1. 先分叉，再收敛（这一步不给人看）

第一反应想到的，是所有人都会想到的。

1. **分叉**：围绕这个题目写 10 条一句话角度。换视角（谁的故事）、换尺度（一秒 / 一百年）、换时间（开头 / 结尾）、换体裁（喜剧 / 寓言 / 纪录 / 惊悚）、换叙述者（没有 / 意想不到的人）。
2. **丢掉前 3 条**。不管它们是什么 —— 那是最顺手的。
3. **留 3 条「意外但成立」的**。
   - 意外：第一次看的人猜不到；
   - 成立：它是从这个题目里长出来的，没有为了意外去拧事实。
4. **选 1 条**，附一句人话理由。

> 用户只看你选的那条和理由。10 条角度不用给他 —— 那是成本，不是价值。

**预测测试（自己做）**：把自己当成没听过这个题目的人，写下「如果只能靠这条题目，我大概会拍成哪 3 支片」。你选的角度如果和其中任何一条撞了主题、关键画面或形式，换下一条。

---

## 2. 一个转折

故事要转，就转**一个明确的改变或反转**。动笔前先写这一行：

```
之前：<…>   /   之后：<…>
```

六种转法，当词汇表用：

| 转法 | 动作 |
| --- | --- |
| **反转** | 角色互换：保护与被保护、追与逃、大与小 |
| **揭示** | 一个细节放大成整体，整体因此换了意思 |
| **变形** | 同一处/同一物跨时间；最后一个状态回答了第一个 |
| **临界** | 事件前一瞬 → 事件 → 它改变了什么 |
| **镜像** | 最后一个画面重复第一个，意思变了 |
| **反差** | 说的是 A，画面是 B，中间的缝就是意思 |

情绪片、人物肖像可以没有转折，但要明确「观众最后带走什么」，并且始终有新东西进来，不能空转。

---

## 3. 结尾先写

先把**最后一个画面或最后一句**写出来。片子落在哪，决定前面要铺什么。

检查：结尾需要的东西（一个物件、一条规则、一个指代、一个数字），是不是都在前三分之一出现过。结尾要有自己的秒数，不能挤在最后 0.3 秒里。

---

## 4. 别解释画面（caption test）

- **旁白不描述画面上的事**。旁白要加画面给不了的东西：潜台词、对照、过去、心里的声音、一个计数、一条规则。
- **字幕测试**：如果这句话可以当这一镜的图注（它只是把画面说了一遍），删掉，或者翻成画面没说的那面。
- **别说道理**。结尾需要一句话才看得懂，说明结尾没写完 —— 回去改画面。
- **可以一个字都没有**。声音和剪辑能说清，而且跨语言。

---

## 5. 字数：给一个可执行的预算

中文口播约 **4.5 字/秒**（舒服的语速，带停顿）。屏幕文字不受语速限制，但要受**阅读**限制：一行汉字超过 14 个字，观众就开始跳读。

| 时长 | 旁白预算 | 单条屏幕文字 | 每镜最多几条 |
| --- | --- | --- | --- |
| 15 秒 | ≤ 65 字 | ≤ 12 字 | 2 |
| 30 秒 | ≤ 130 字 | ≤ 14 字 | 3 |
| 60 秒 | ≤ 260 字 | ≤ 16 字 | 4 |
| 3 分钟 | ≤ 780 字 | ≤ 18 字 | 5 |

> 超了不是「信息量大」，是「观众读不完」。`h2v check story.json` 会按这张表算给你看。

## 6. 陈词滥调清单（中文）

写下来就删。这些词组让文案听起来像 PPT 生成器：

**开场类**：在这个时代 / 随着……的发展 / 众所周知 / 让我们一起来 / 今天我想聊聊
**总结类**：总而言之 / 值得一提的是 / 不难发现 / 由此可见 / 综上所述
**形容类**：赋能 / 抓手 / 闭环 / 生态 / 颠覆 / 革新 / 全新升级 / 极致体验 / 匠心智造
**空转类**：让我们一起见证 / 未来已来 / 无限可能 / 开启新篇章 / 重新定义

替换原则：**换成一个可以拍出来的动作或一个具体数字**。
「极致体验」→「按下到出片，4 秒」；「赋能创作」→「不会写代码的人，也能改这一行」。

---

## 7. 给用户看之前，过两遍

1. **读出声**。读着打结的地方，就是观众听不懂的地方。
2. **砍 30%**。第二遍不是润色，是删。删完通常更清楚。

---

## 8. 首次观看者检查

找一个完全不知道背景的人（或把自己当成他），只看一遍，问三个问题：

- 这是关于什么的？（一句话能答上来吗）
- 中间那下转折，你注意到了吗？
- 最后留下了什么？

三个都答得上来，才算写完。

## 落到 story JSON 上

模板的 `story` 是一个数组，每一镜：

```json
{ "id": "hook", "dur": 3, "kicker": "v1.8 · 镜头", "lines": ["切点", "落在拍上"], "sub": "…", "camera": "dolly in, 3s" }
```

- `lines` 是屏幕大字：**一行 ≤ 12 字**，最多 3 行（模板会自动缩字号，但缩到看不清就没意义）。
- `sub` 是一句补充：它应该说出 `lines` 没说的那面，而不是把 `lines` 再说一遍。
- `camera` 是这一镜的镜头（见 `h2v camera`）：**推=紧张或重要，拉=释放或交代，摇=扫视，升降=尺度，手持=在场**。

`h2v check story.json` 会把字数、每镜条数、陈词滥调、缺失的转折一次性列出来。
